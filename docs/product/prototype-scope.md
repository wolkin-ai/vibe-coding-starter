# プロトタイプ最小構成スコープ

## ゴール

アップロードした顧客写真または参考画像を起点に、スタイルパラメータを調整しながら複数の仕上がり案を生成・比較・承認できる最小機能を提供する。

## ユーザーフロー（β）

1. ログイン（Owner/Stylistロール）
2. プロジェクト選択または作成
3. 画像アップロード（トリミングは任意。生成時に自動調整）
4. 希望スタイルパラメータの設定（長さ/カラー/前髪/質感など）
5. 生成ジョブ実行 → 複数のスタイル案が返却されギャラリー表示
6. 各スタイル案に対して承認・却下・メモ入力
7. 承認済み案をエクスポート（PNG/JPEG、共有用リンク）

## 必須機能

- 認証とロール管理（Supabase Auth想定）
- プロジェクト・アセット管理（原画像、生成案、ステータス）
- スタイルパラメータUI：プリセット＋詳細スライダー
- 画像生成ワーカー：Google Gemini（Nano Banana）APIを用いた複数案生成
- 承認フロー：`draft` → `reviewing` → `approved/rejected`
- エクスポート：承認案のみダウンロード／共有リンク生成

## 非対象事項（後続計画）

- 自動タグ付け・文章生成
- 業務システムへの入稿連携やレギュレーションチェック機能
- モバイル撮影ガイドやリアルタイムプレビュー
- Slack/Notion等の外部連携（βでは通知なし）
- 課金・クレジット管理

## 技術スタック（暫定）

- フロント：Next.js（App Router）+ Tailwind CSS + Zustand/React Query等の状態管理
- バックエンド：Next.js API Routes（REST）
- ストレージ：Supabase StorageまたはS3互換バケット
- DB：PostgreSQL（Supabase）
- 生成：Google Gemini Image API（公式APIキー）
- ジョブ実行：BullMQ（Redis）またはSupabase Edge Functions

## リスク・制約

- 生成結果の品質がプロンプト依存のため、プリセット調整とプロンプトテンプレを継続改善する必要がある。
- API利用コストとレート制限を監視し、βのユーザー数を制御する。
- アップロード画像に個人情報が含まれる場合の保護・削除フローを別途策定する。
