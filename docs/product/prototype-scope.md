# MVPスコープ

## ゴール

- ブランド設定を前提にせず、ムードプリセットと手動パラメータだけでカットモデルとヘアスタイルを生成・管理できる最小構成を提供する。

## ユーザーフロー（MVP）

1. ログイン → ムードプリセット（ギャル／モード／ナチュラル等）を選択、または「おまかせ」で開始。
2. カットモデル生成：性別・年齢帯・顔型・ムードを指定し、候補を生成・保存。
3. ヘアスタイル生成：
   - a. 保存済みカットモデルを指定してスタイルを生成。
   - b. モデル指定なしでムード＋ヘアパラメータからバッチ生成。
   - c. 参考画像をアップロードし、スタイル転写。
4. ギャラリーで生成結果を確認し、タグ・ステータスを付与してカタログへ登録。
5. カタログをステータス／タグ／ムードで整理し、SNS向けテンプレートで書き出す。

## 対象機能

- システム提供のムードプリセット（ギャル／モード／フェミニン／K-Beauty など）と自由入力パラメータの切り替え。
- カットモデル生成（Google Gemini 2.5 Flash Image）／お気に入り保存・再生成。
- ヘアスタイル生成（モデル指定、ムード別バッチ、参考画像転写）。
- ギャラリー＆カタログ管理（ステータス：draft/reviewing/approved/archived、タグ、削除）。
- 出力テンプレート：Instagram 1:1、Hot Pepper 3:4、X 16:9。
- 生成ジョブの履歴・コスト見積もり表示（簡易ログ）。

## 非対象（次フェーズ以降）

- 実在人物アップロードの承認フロー。
- チームレビュー、コメント、通知などのワークフロー機能。
- マルチテナント（複数ブランド）管理や詳細な分析機能。
- 多言語対応・外部公開ページ生成。

## 技術スタック（暫定）

- フロントエンド：Next.js（App Router）/ TypeScript / Tailwind CSS / Zustand + React Query。
- API：Next.js API Routes（Prompt Builder、Gemini呼び出し、ストレージ署名URL）。
- 画像生成：Google Gemini 2.5 Flash Image API（生成・編集・転写）。
- バックグラウンド処理：BullMQ（Redis）または Supabase Edge Functions。
- ストレージ：S3互換バケット（原画像、生成画像、参照画像を分離）。

## リスク / 考慮点

- プリセットの粒度が粗いと多様性が確保できない／逆に緩すぎるとムードがばらつく。
- 生成結果にムードを反映させるプロンプトのチューニングが必要。
- Google Gemini のレート制限・利用コスト。
- AI生成物であることの明示、人物表現に関する倫理ポリシー徹底。

## MVP完了の判断基準

- プリセット＋手動パラメータで 4〜8 枚の候補を安定生成できる。
- カットモデル／ヘアスタイルの保存・タグ付け・ステータス変更がカタログ画面に反映される。
- 主要SNSアスペクト比テンプレートでダウンロードができる。
- 生成ジョブ履歴から再生成に必要な情報（ムード、パラメータ、コスト見積もり）が把握できる。
