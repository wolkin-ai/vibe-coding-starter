# MVPスコープ

## ゴール

- 生成AIのみでカットモデルとヘアスタイル画像を作成し、ブランド世界観に沿ったビジュアル資産を蓄積する最小構成を実現する。

## ユーザーフロー（MVP）

1. ログイン → ブランドテーマ（ギャル／モード等）を作成または選択
2. カットモデル生成：性別（女性）、年齢帯、テイストを指定してモデル画像を生成・保存
3. ヘアスタイル生成
   - a. 保存済みカットモデルを選び、ヘアパラメータ（長さ・カラー・ボリューム等）を指定して複数枚生成
   - b. モデル指定なしでブランドテーマ＋ヘアパラメータからバッチ生成
   - c. 参照ヘア画像をアップロードし、生成済みモデルへスタイル転写
4. 生成結果をギャラリーで確認し、お気に入り登録 → カタログに追加
5. カタログをブランドテーマ別に整理し、必要に応じてダウンロード（SNS/Hot Pepper掲載想定フォーマット）

## 対象機能

- ブランドテーマ管理（プリセット＋カスタムキーワード・カラーパレット）
- カットモデル生成（Google Gemini 2.5 Flash Image）／お気に入り保存・再生成
- ヘアスタイル生成（パラメータ指定、参照画像適用、バッチ出力枚数の指定）
- ギャラリー＆カタログ管理（お気に入り、タグ、ステータス）
- 出力：Instagram／Hot Pepper Beauty／X向けアスペクト比の書き出しテンプレート
- 生成ジョブ管理：ステータス、予測コスト、生成履歴の保存

## 非対象（次フェーズ以降）

- 実在人物画像のアップロード処理
- 外部共有リンク、承認ワークフロー、通知連携
- 高度な分析（ブランド別コンバージョン等）
- 多言語対応、顧客向け公開サイト生成

## 技術スタック（暫定）

- フロントエンド：Next.js（App Router）/ TypeScript / Tailwind CSS / Zustand + React Query
- API：Next.js API Routes または軽量FastAPI（Prompt Builder、Gemini呼び出し、ストレージ署名URL）
- モデル生成：Google Gemini 2.5 Flash Image API（画像生成・編集・転写）
- ジョブ処理：BullMQ（Redis）またはSupabase Edge Functionsでの非同期キュー
- ストレージ：S3互換（原画像、生成画像、参照画像をバケット分離）
- データベース：PostgreSQL（Supabase）

## リスク・制約

- Gemini 2.5 Flash Imageの利用上限・料金変動に応じたバッチ枚数制御が必要
- ブランドテーマ定義が曖昧だと生成結果がばらつくため、初期テンプレートの精度が重要
- SynthID等の生成メタデータを保持し、社外への利用ポリシーを明示する必要がある
- リアル寄りの生成品質はプロンプト設計に依存するため、検証サイクルとプロンプト管理が不可欠
